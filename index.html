    Project Overview

    Passport Sahayak is an AI-powered passport assistance application designed to help users understand passport application procedures, required documents, eligibility criteria, and passport-related information.

    Problem Statement

    Passport information is spread across multiple documents and official guidelines. Finding the correct information manually can be time-consuming.

    Project Objective

    To build an intelligent assistant that answers passport-related questions using uploaded knowledge documents and Generative AI.

    Technical Information

    Backend: Java, Spring Boot

    AI Integration: Spring AI, OpenAI

    Architecture: Retrieval-Augmented Generation (RAG)

    Databases: MariaDB, Vector Database

    Document Processing: PDFBox, Apache POI

    Security: Spring Security

    Documentation: Swagger/OpenAPI

    Detailed Project Explanation

    1. Project Introduction: An AI-powered application that helps users understand passport procedures, documents, eligibility, and services.
    2. Problem Statement: Passport information is distributed across multiple documents and guidelines, making manual searching time-consuming.
    3. Project Objective: Provides relevant answers to passport-related questions using a document knowledge base and AI.
    4. Technology Architecture: Java and Spring Boot are used for the backend, with Spring AI and OpenAI for Generative AI integration.
    5. What is RAG?: Retrieval-Augmented Generation combines document retrieval with a Large Language Model to generate answers using relevant knowledge.
    6. Why RAG?: Instead of depending only on the AI model's general knowledge, the system retrieves relevant information from provided documents.
    7. User Management: Manages user information and provides access to the application.
    8. Knowledge Base Management: Maintains passport-related documents as the knowledge source for answering questions.
    9. Document Upload: Authorized users can upload knowledge documents in PDF, DOCX, and TXT formats.
    10. Document Extraction: Apache PDFBox extracts text from PDF files, and Apache POI processes supported Word documents.
    11. Text Preprocessing: Extracted content is cleaned and organized before further processing.
    12. Text Chunking: Large documents are divided into smaller chunks to improve relevant information retrieval.
    13. Embedding Generation: Each text chunk is converted into a numerical vector representation called an embedding.
    14. Vector Database: Stores generated embeddings and associated document information for similarity-based retrieval.
    15. MariaDB Database: Stores structured application information, including users, applications, appointments, audit logs, and chat records.
    16. Separate Databases: The application uses passportsahayak_db for application data and vectordb for vector-based knowledge retrieval.
    17. Knowledge Ingestion API: The POST /api/v1/kb/ingest API initiates the knowledge-base ingestion process.
    18. Ingestion Workflow: Uploaded documents are extracted, divided into chunks, converted into embeddings, and stored for future retrieval.
    19. User Query: Users can ask questions such as which documents are required for a passport application or how to apply.
    20. Query Embedding: The user's question is converted into a vector representation using an embedding model.
    21. Similarity Search: The vector database identifies document chunks that are semantically similar to the user's question.
    22. Context Retrieval: The most relevant document content is retrieved and supplied as context to the AI model.
    23. AI Response Generation: OpenAI receives the user's question and retrieved context and generates a natural-language response.
    24. Response Delivery: The generated answer is returned to the user through the backend API.
    25. Application Management: Includes modules to manage passport application records and associated information.
    26. Status History: Maintains application status history so changes can be tracked.
    27. Appointment Management: Manages appointment-related records and information.
    28. Chat Management: Maintains chat sessions and messages to support conversations and record interactions.
    29. Security and Documentation: Spring Security supports access control, while Swagger/OpenAPI documents and helps test APIs.
    30. Project Outcome: Combines Spring Boot, Generative AI, and RAG to retrieve relevant information and generate understandable passport assistance responses.

    Project Overview

    MIPI DSI stands for Mobile Industry Processor Interface – Display Serial Interface. It is a high-speed communication interface used to connect a host processor with a display module.

    Note: The available project notes provide a technical study guide for MIPI DSI, not confirmation of every implementation detail. The explanation below describes the technology and typical engineering concepts. Your resume separately mentions SystemVerilog, UVM, AHB configuration, and scoreboard-based checking.

    Project Objective

    To understand how display information is transferred from a processor to a display panel efficiently, using high-speed communication, fewer physical connections, and low power.

    Detailed Technical Explanation

    1. Project Introduction: MIPI DSI is a high-speed serial communication interface between a host processor and a display module.
    2. Project Objective: Transfers display information efficiently with low power consumption and fewer physical connections.
    3. Problem Statement: Traditional display interfaces can require more physical connections and may have limitations in bandwidth and power efficiency.
    4. Applications: Used in smartphones, tablets, laptops, smartwatches, automotive displays, and embedded display systems.
    5. Host Processor: Generates or receives image data and controls the display interface.
    6. Display Module: Receives transmitted data and converts it into visual output on the screen.
    7. DSI Host Controller: Manages protocol-level communication between the processor and display.
    8. Physical Layer: MIPI DSI commonly operates over MIPI D-PHY, which handles electrical signaling and physical data transmission.
    9. Data Lanes: Multiple data lanes can transmit information at high speeds. The number of lanes depends on the system configuration.
    10. Clock Lane: Traditional D-PHY configurations use a dedicated clock lane to synchronize high-speed data transmission.
    11. High-Speed Mode: Used to transfer large amounts of display data efficiently.
    12. Low-Power Mode: Supports low-speed control communication and helps reduce power consumption.
    13. Command Mode: The host sends commands and display data to update the display.
    14. Video Mode: The host continuously transmits pixel data according to configured display timing.
    15. MIPI DCS: The Display Command Set defines standardized commands for controlling display functions.
    16. Display Initialization: The panel generally requires initialization commands to configure its operating parameters before displaying content.
    17. Pixel Data: Pixel information represents screen colors. Common formats include RGB565, RGB666, and RGB888.
    18. Packet Structure: DSI uses packets containing protocol information and payload data to transfer commands and pixel information.
    19. Short Packets: Commonly used for commands or control information with small payloads.
    20. Long Packets: Used to carry larger amounts of data, including pixel information.
    21. Synchronization: Video transmission uses horizontal and vertical synchronization information to maintain correct frame display.
    22. Display Timing: Horizontal sync, vertical sync, front porch, and back porch determine display update timing.
    23. Error Handling: Protocol-defined error detection and reporting mechanisms help identify communication problems.
    24. Bandwidth: Required bandwidth depends on display resolution, refresh rate, pixel format, and the number of available lanes.
    25. Power Efficiency: MIPI DSI supports high-performance display communication while reducing power consumption and electromagnetic interference.
    26. Hardware Integration: A typical implementation connects the processor's DSI host interface to a compatible display module through the physical-layer interface and connector.
    27. Software Configuration: Software or firmware configures display parameters, initialization sequences, interface modes, and transmission settings.
    28. Testing: Typical testing includes display initialization, communication, image output, resolution, refresh rate, and correct display behavior.
    29. Challenges: Common challenges include lane configuration, timing mismatches, incorrect initialization commands, signal integrity issues, and communication failures.
    30. Project Outcome: MIPI DSI enables reliable, high-speed communication between the processor and display panel while maintaining efficient power usage.
